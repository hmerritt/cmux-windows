# Windows keyboard shortcuts

Settings > Actions > Keyboard Shortcuts lists every action in the current cmux
registry, its default, current override and Windows availability. The command
palette exposes available actions, including actions unbound by default.

Command maps to Ctrl, Option maps to Alt. macOS has separate Command and Control
modifiers; merging both into Ctrl would make different actions collide. Actions
using **Command+Control** therefore use **Ctrl+Shift+Space**, followed within
1.5 seconds by the remaining shortcut with Command replaced by Ctrl. For example,
Next Workspace is `Ctrl+Shift+Space`, then `Ctrl+]`. Surface numbering uses
`Alt+1` through `Alt+9`; workspace numbering uses `Ctrl+1` through `Ctrl+9`.
The ninth digit selects the last item; missing items at digits 1–8 do nothing.
Pane resize uses `Ctrl+Alt+Shift+H/J/K/L` to avoid collisions with translated
Command shortcuts. F11, Ctrl+Tab, Ctrl+PageUp/PageDown and F3 aliases appear below.

The shortcut editor accepts a stroke (`ctrl+alt+d`), a two-stroke chord
(`ctrl+b, c` or `["ctrl+b","c"]`), or an empty value to unbind. Reset removes
that action's override and restores its factory binding and aliases. Explicit
overrides replace the entire binding, including factory aliases. When a custom
binding collides with a factory binding, the custom binding takes precedence;
conflicts between custom bindings should be resolved by rebinding or unbinding
one of them. Windows reserves some OS shortcuts before an app can receive them.

## Configuration

The app reads `~/.config/cmux/cmux.json` (JSONC with comments and trailing commas).
Changes reload automatically. The editor changes only `shortcuts.bindings.<id>`
and preserves unrelated settings and comments. A malformed file or binding keeps
the last valid shortcut configuration active and displays an error in the editor.
Other settings in this file are not imported into the Windows appearance editor.

```jsonc
{
  "shortcuts": {
    "bindings": {
      "newSurface": ["ctrl+b", "c"],
      "splitRight": "ctrl+alt+d",
      "closeWorkspace": null
    },
    "when": {
      "closeTab": "terminalFocus && !terminalAlternateScreen"
    }
  }
}
```

`cmd`, `command`, `ctrl`, `control`, `alt`, `option`, `shift`, `meta`, `win`
and `super` modifier names are accepted. `cmd` is translated to Ctrl; a single
stroke containing both `cmd` and `ctrl` uses the Windows prefix described above.
Number-family bindings must end in a digit from 1 to 9.

Supported extra `when` guards are boolean context names combined with `!`, `&&`,
`||` and parentheses: `terminalFocus`, `browserFocus`, `sidebarFocus`,
`textInputFocus`, `terminalAlternateScreen`, `terminalCopyMode`,
`commandPaletteVisible` and `appFocus`. These guards narrow an action's built-in
availability. Other macOS predicate operators/context keys are not yet supported.
App shortcuts are suppressed during dialogs, IME composition and AltGr input.
Browser-specific bindings route through the guest while a page owns focus.

Copy mode currently provides line selection with Up/Down or j/k, Shift to extend,
PageUp/PageDown and g/Shift+g to navigate, y to copy, and Escape/Enter to exit.
This is not the complete Ghostty copy-mode command set. Terminal Ctrl+K,
Ctrl+Shift+C/V and Ctrl+=/-/0 retain the Windows terminal editing behavior;
these terminal defaults are separate from cmux-owned action overrides.

## Availability

All 169 registry actions are listed below; 116 currently have Windows handlers.
Unavailable actions do not intercept keys. Remaining actions require features
absent from this port, including Cloud/team integration, workspace groups/status
and session reopening, the full right sidebar/files/text-box UI, canvas layout,
markdown/diff viewers, iOS simulator integration, screenshot attachment and the
system-wide window hotkey. Their presence in the registry does not implement
those features. Notifications currently contain unread pane attention, so both
bulk notification actions clear that unread view; there is no read-history view.

The table is generated by `npm run build:shortcuts` from the Swift registry and
Windows availability map. Native macOS bindings and documentation are unchanged.

## Verification

`npm run test:shortcuts` drives real Electron keyboard events in an isolated
profile, including terminal and browser focus, pane/tab/workspace navigation,
native browser actions, live configuration edits and the shortcut editor.
The Ctrl+D regression failed before the implementation (`cd20a8c52d`) and passes
with it. The suite passes at 100% and 150% display scaling. `npm test` also checks
binding parsing, precedence, numbered chords, context guards and JSONC updates.
The packaged smoke test checks Ctrl+D against the shipped executable.

The shortcut editor's new UI strings and all action labels cover nine locales.
This document is English only; the repository catalog checker does not verify
Windows UI translation completeness.
